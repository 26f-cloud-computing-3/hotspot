# 기능 정리

## 서비스 개요

좋아하는 장소를 관리하고 사람들과 공유하는 서비스

## 핵심 엔티티

- **User**: 서비스 사용자
- **Place**: 지도상의 장소 (현재 지도 provider의 검색 결과 기반)
- **Collection**: 유저가 좋아하는 장소들을 묶어놓은 단위. 유저 1명이 N개 소유
- **Follow**: 유저 간 단방향 팔로우 관계

## 핵심 기능

### 1. 장소 컬렉션 저장
- 설명: 유저가 좋아하는 장소를 컬렉션 단위로 저장한다.
- 우선순위: MVP
- 상태: 구현됨 (장소 찾기에서 담기 · 제외, 컬렉션 상세에서 담긴 장소 조회 · 제외)
- 한 장소를 여러 컬렉션에 담을 수 있고, 한 컬렉션에 같은 장소는 한 번만 담긴다. 컬렉션당 장소 수 상한은 없다.

### 2. 컬렉션 다중 소유
- 설명: 유저 한 명이 여러 개의 컬렉션을 소유할 수 있다 (예: "서울 카페", "혼자 가기 좋은 곳" 등 주제별 분리).
- 우선순위: MVP
- 상태: 구현됨 (목록 · 생성. 이름 변경/삭제는 미구현)

### 3. 컬렉션 공개/비공개 설정
- 설명: 각 컬렉션마다 공개(다른 유저가 조회 가능) / 비공개(본인만 조회 가능) 여부를 설정할 수 있다. 공개 단계는 공개/비공개 2단계만 있고, "팔로워 공개" 같은 중간 단계는 없다.
- 우선순위: MVP
- 상태: 구현됨 (공개 전환은 컬렉션 카드의 수정 다이얼로그에서. 공개 컬렉션은 유저 프로필에서 열람)
- 공개 컬렉션은 로그인한 유저라면 팔로우 여부와 무관하게 조회할 수 있다. 조회만 가능하고, 수정 · 삭제 · 장소 담기 · 제외는 소유자만 한다. 비공개 컬렉션은 소유자 외에는 존재 여부도 알 수 없다.
- 비공개 → 공개 전환 시, 이미 저장돼 있던 장소들도 함께 공개된다. (컬렉션 단위로 공개 여부가 정해지고, 장소별 개별 공개 설정은 없음)

### 4. 유저 간 팔로우
- 설명: 유저는 다른 유저를 즉시(승인 없이) 팔로우할 수 있다. 팔로우의 목적은 (a) 상대방의 공개 컬렉션 열람, (b) 피드 구독 두 가지다.
- 우선순위: MVP
- 상태: 구현됨 (팔로우/언팔로우 · 내 팔로워/팔로잉 목록 · 이름/핸들 검색 · 상대방 프로필과 공개 컬렉션 열람)
- 공개 컬렉션 열람에 팔로우가 필요하지는 않다. 팔로우를 조건으로 걸면 "팔로워 공개" 단계가 생기기 때문이다. 팔로우는 피드 구독 여부만 가른다.
- 유저 프로필에는 팔로워/팔로잉 수 · 목록을 노출하지 않는다.
- 팔로워 목록 공개 범위: followee(팔로우 받는 사람)는 자신의 follower 목록을 볼 수 있다. 제3자는 다른 유저의 follower 목록을 조회할 수 없다.

### 5. 피드
- 설명: 내가 팔로우한 유저들의 활동(예: 공개 컬렉션에 장소 추가/신규 공개 컬렉션 생성 등)을 모아 보여준다.
- 우선순위: MVP
- 상태: 구현됨 (`GET /api/feed`, 피드 화면. 노출 규칙은 `docs/database.md`의 「피드」 참고)
- 피드 이벤트 종류: 장소 추가, 장소 제외, 컬렉션 추가(공개로 생성 · 공개 전환), 컬렉션 수정(이름 변경), 컬렉션 제외(삭제)
- 지금 공개인 컬렉션의 활동만 노출된다. 비공개 컬렉션에 대한 활동은 전부 노출되지 않고, 컬렉션을 비공개로 바꾸면 공개 시절의 활동도 함께 사라진다. 비공개 전환 자체는 피드에 알리지 않는다.

### 6. 인기 장소
- 설명: 내가 팔로우한 유저들이 공개 컬렉션에 담은 장소를, 담은 사람이 많은 순으로 보여 준다.
- 우선순위: MVP 이후 (이슈 #41)
- 상태: 구현됨 (`GET /api/places/popular`, 「인기」 메뉴. 집계 규칙은 `docs/database.md`의 「인기 장소」 참고)
- 담은 사람 수로 순위를 매긴다. 한 사람이 같은 장소를 여러 컬렉션에 담아도 1명이고, 비공개 컬렉션은 세지 않는다.
- 결과가 적거나 없어도 다른 데이터(서비스 전체 인기 등)로 채우지 않는다. 없으면 빈 상태 화면을 보여 준다.
- 카테고리 필터, 지역별 인기, 기간 제한은 후속 작업이다.

### 7. 내 컬렉션 카테고리 계층 분석
- 설명: 내 컬렉션에 담긴 장소의 카카오 카테고리 경로를 계층별로 집계해 보여 준다.
- 우선순위: 데이터 수집 · 정제 · 분석 시연
- 상태: 구현됨 (`GET /api/collections/{id}/category-stats`, 내 컬렉션 상세의 「컬렉션 카테고리 구성」 카드)
- 저장된 `category`를 ` > ` 단위로 나눠 부모부터 자식까지 각 단계의 장소 수를 누적한다.
- 기존 장소 스냅샷만 사용하므로 통계 조회 시 카카오 API를 다시 호출하지 않으며 별도 집계 결과도 저장하지 않는다.
